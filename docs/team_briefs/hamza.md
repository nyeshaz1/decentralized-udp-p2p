## Task H1: Chunker, manifest, placement, chunk store (Mon 23) in src/p2p/storage/
- `manifest.py`: `@dataclass Manifest(file_id: bytes(16), size, chunk_size, n_chunks, file_hash: bytes(32), name, chunk_hashes: list[bytes])` with `pack() -> bytes` and `Manifest.unpack(bytes)` exactly as the FILE_MANIFEST layout in protocol.md. `file_id = file_hash[:16]`.
- `chunker.py`: `build_manifest(path) -> Manifest` (reads in 64 KiB chunks, SHA-256 per chunk and per file, `n_chunks = ceil(size/chunk_size)`, last chunk may be shorter, name = base name only); `read_chunk(path, idx) -> bytes`; `assemble(chunks, dest)`.
- `placement.py`: `holders(file_id: bytes, idx: int, alive_ids: list[int], r: int = REPLICATION) -> list[int]`. EXACT rule from protocol.md 6.2: score(p) = first 8 bytes, big-endian u64, of SHA-256(file_id + idx as u32 big-endian + p as u32 big-endian); top r scores win, ties to the lower peer id; if fewer than r peers exist return all.
- `store.py`: `ChunkStore(root)`: `put(fid, idx, data)` (atomic: write temp file then os.replace), `get`, `has`, `delete`, `list()`; files at `<root>/chunks/<fid hex>_<idx>.chunk`; thread-safe.
- `manager.py`: `StorageManager(data_dir, my_id)` holds manifests `{fid: Manifest}`, chunk map `{(fid, idx): set(holder ids)}`, the ChunkStore; `export_state() -> (manifest_payloads: list[bytes], chunk_map: list[(fid, idx, list[int])])` and `import_state(manifests, chunk_map)` (merge, idempotent, never overwrite local knowledge with less), plus helpers `add_manifest`, `add_holder`, `remove_holder`, `holders_alive(fid, idx, alive_ids)`.
Tests: manifest pack/unpack round trip; hash of a 3 MB random file; placement deterministic and independent of list order; with 4 peers every chunk has exactly 2 distinct holders and no peer holds all chunks of a 3 MB file; removing one peer changes only a minority of chunk owners (HRW property); chunk store survives concurrent puts.

## Task H2: Transfer service (Tue 24 to Thu 26) in src/p2p/transfer/transfer.py
`TransferService(transport, membership, storage, my_id)`; methods `start()`, `stop()`, `share_file(path)`, `list_files()`, `download(name_or_fid_hex, dest_dir, progress_cb=None) -> str`, `chunk_holders(name)`. Register handlers for FILE_MANIFEST, CHUNK_STORE, CHUNK_REQUEST, CHUNK_DATA, CHUNK_ERROR, REPLICA_UPDATE. Payload layouts are in protocol.md section 3 (write and test your own encode/decode helpers in `transfer/messages.py`). Slow work runs in worker threads, not in handlers.
- **share_file(path)** (protocol 6.2): require at least 3 alive peers including me (else raise a clear error). Build the manifest, send FILE_MANIFEST reliably to all alive peers, then for each chunk compute `holders()` over alive ids plus me and send CHUNK_STORE to each holder (store locally if I am a holder). Holder verifies SHA-256 against the manifest, stores, and sends REPLICA_UPDATE(ADD) to everyone. The seeder keeps no chunk it is not a holder of. Pace sending (small window of outstanding chunks) so the transport is not flooded.
- **Handover on join** (6.2): on membership event "join", recompute placement over the new alive set. For each chunk where the new peer is now a holder and lacks it, the current holder with the lowest id sends CHUNK_STORE. After the new holder's REPLICA_UPDATE(ADD), a former holder that is no longer in the top r deletes its copy and sends REPLICA_UPDATE(REMOVE). Never delete a chunk until the ADD for its replacement is seen, so copies never drop below 2.
- **download(...)** (6.4): look up the manifest; build the list of missing chunks; use 4 to 8 worker threads. For each chunk choose among ALIVE holders, alternating (round robin starting at idx % n) so at least 2 different peers serve in parallel; at most 4 outstanding requests per peer. Send CHUNK_REQUEST; wait for CHUNK_DATA or CHUNK_ERROR with a 5 s timeout; verify SHA-256 against `chunk_hashes[idx]`; on mismatch, error or timeout retry on a different holder (max 3 tries per holder). Write chunks to a temp part file, then assemble and verify `file_hash`; delete the part file on failure. A chunk this peer holds itself is read from disk locally. Return the final path. `progress_cb(done, total)` after each chunk. Print/log which peer served each chunk (needed for the demo).
- **Failover** (6.5): on membership event "fail"/"leave" of a holder, remove it from candidate lists, cancel its outstanding requests immediately and re-request those chunks from another holder; do not restart the download. If no alive holder remains for a chunk, raise a clear error.
- **Serving**: CHUNK_REQUEST handler reads the chunk from disk and replies CHUNK_DATA, or CHUNK_ERROR (NOT_FOUND / UNKNOWN_FILE). Serve in a worker thread, limit to 8 concurrent serves (reply BUSY beyond).
- **Stretch Fri 27 (only if core is green): re-replication.** On "fail"/"leave", for every chunk with fewer than R alive holders, the alive holder with the lowest id sends CHUNK_STORE to the new top-R peer lacking it; holder replies REPLICA_UPDATE(ADD).
Tests with FakeNetwork (tests/test_transfer.py), 4 fake peers with a shared membership stub: share a 3 MB file and check every chunk is on exactly 2 peers and no peer has all chunks; a 5th peer downloads and the file hash matches; downloader uses at least 2 distinct source peers (check from logs or counters); `kill()` one source midway (use a hook that kills after N chunks) and the download still completes; corrupt one chunk on one holder (flip a byte on disk) and the download recovers from the other holder; a joiner receives its share and total copies of every chunk stay >= 2; downloading with a dead sole holder raises the clear error.
